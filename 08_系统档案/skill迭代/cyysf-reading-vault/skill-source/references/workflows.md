# Reading Workflows

## New Book

1. Ask the user why they want to read the book.
2. Record reading purpose, questions, relevant life/work scenarios, expected change, and reading strategy.
3. Use the reading-method judgment:
   - A: intensive read
   - B: normal read
   - C: light read or trial
4. Score or discuss problem relevance, expected cognitive gain, action value, structure value, and reread willingness.
5. Default to B unless the user’s current problem strongly justifies A.
6. Create or update `01_书籍记录/<book>/01_读前目标与读法判断.md`.
7. Create or update `01_书籍记录/<book>/00_书籍总览.md` and `06_方法实践记录.md`.
8. Use the goal and reading level later during highlights, weekly reviews, 20%-30% reassessment, and final book review.

## Reading Level Reassessment

When the user reaches about 20%-30% of a book:

1. Check whether the book is still answering the original reading questions.
2. Ask whether it is changing the user’s judgment or producing action value.
3. Decide whether to maintain, upgrade, downgrade, or pause the reading level.
4. Record the reason if the level changes.

## Daily Lightweight Review

Daily work should protect the user's reading habit and thinking energy. Do not turn every day into full filing work.

1. Pull or receive same-day highlights when needed.
2. If many highlights exist, ask the user to choose 1-3 thinking seeds or one group to discuss.
3. Ask questions before summarizing. The user gives their own reflection first.
4. Summarize only after the user answers:
   - why it touched them
   - which reading goal it answers
   - usable judgment
   - possible action or reminder
   - possible theme
5. Write a lightweight daily thinking note in `01_书籍记录/<book>/02_每日思考/` or update `00_入口/本周阅读工作台.md`.
6. Put unprocessed but valuable highlights into the weekly workbench.
7. Do not force daily theme-card, book-card, or action-principle updates.
8. Write agent log and sync GitHub when files are changed.

## Weekly Review

1. Review `00_入口/本周阅读工作台.md` and daily thinking notes.
2. Pull or list the week’s important highlights if needed.
3. Group thinking seeds by topic.
4. Let the user choose discussion groups when judgment is needed.
5. Extract the week’s top 3 insights.
6. Update 1-3 theme cards only when there is reusable substance.
7. Choose or review one action experiment in `03_行动实践库/行动实践看板.md`.
8. Write stage review in `01_书籍记录/<book>/03_阶段复盘/`.
9. Sync to GitHub.

## Book Completion

When a book is complete:

1. Update book status and progress.
2. Review original reading goals.
3. Confirm the final reading level: A, B, or C.
4. Identify which questions were answered and which remain open.
5. Write or update `01_书籍记录/<book>/04_读后总结.md`.
6. If A-level, consider quick reread and write `01_书籍记录/<book>/05_整书脉络.md`.
7. If B-level, produce a concise completion summary and one possible action principle.
8. If C-level, preserve only useful triggers and do not force a full summary.
9. Extract 1-3 durable action principles when appropriate.
10. Review whether at least one principle entered action practice.
11. Update long-term theme cards only when there is reusable substance.
12. Record method feedback from this book in `06_方法实践记录.md`.
13. Sync to GitHub.

## Do Not

- Do not replace the user's thinking with a direct summary.
- Do not dump every highlight into theme cards.
- Do not make the system heavier just to be complete.
- Do not revive the paused reward/points mechanism unless the user asks.
