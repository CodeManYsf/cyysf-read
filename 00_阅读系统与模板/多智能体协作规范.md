# 多智能体协作规范

## 设计目的

这个阅读知识库不应该只绑定 Codex。后续用户可能会用 WorkBuddy 或其他智能体平台在手机、电脑或不同环境中继续维护阅读记录。

本规范的目的，是让不同智能体都能维护同一个阅读知识库，同时避免记录来源混乱、重复总结、互相覆盖或无法追溯。

## 基本定位

```text
GitHub 仓库 = 唯一主库
阅读系统目录 = 内容沉淀区
智能体协作记录 = 操作留痕区
Codex / WorkBuddy / 其他平台 = 不同入口
```

不管使用哪个平台，阅读内容都进入统一的阅读系统：

- `01_每日阅读回收`
- `02_每周阅读复盘`
- `03_书籍卡片`
- `04_主题卡片库`
- `05_行动原则库`
- `00_阅读系统与模板`

平台本身做过什么，才进入：

- `10_智能体协作记录`

## 目录设计

```text
10_智能体协作记录/
  Codex/
  WorkBuddy/
  其他平台/
```

每个平台只在自己的目录里记录操作日志。

## 平台协作记录模板

```text
# 智能体协作记录

日期：
平台：
任务：

## 操作概述

## 修改文件

## Git 提交

提交信息：
提交哈希：

## 备注
```

记录要求：

1. 简单写清楚做了什么即可。
2. 不把用户的完整阅读感悟写到这里。
3. 阅读感悟、总结和行动原则进入对应阅读目录。
4. 如果未提交或未推送，要在备注中说明原因。

## 标准协作流程

### 1. 开始前

```bash
git status
git pull --ff-only
```

如果 `git pull --ff-only` 失败，说明远程和本地有分歧，不要继续改动，先告诉用户。

### 2. 工作中

根据任务类型写入对应目录：

| 任务 | 写入位置 |
|---|---|
| 每日阅读复盘 | `01_每日阅读回收` |
| 每周复盘 | `02_每周阅读复盘` |
| 书籍总结/读后回顾 | `03_书籍卡片` |
| 主题沉淀 | `04_主题卡片库` |
| 行动原则 | `05_行动原则库` |
| 方法调整 | `00_阅读系统与模板` |
| 平台操作记录 | `10_智能体协作记录` |

### 3. 结束后

```bash
git status
git add .
git commit -m "[平台] 类型：YYYY-MM-DD 主题"
git push
```

提交信息示例：

```text
[Codex] 方法调整：2026-06-03 增加多智能体协作规范
[WorkBuddy] 阅读复盘：2026-06-04 道商范蠡读后回顾
```

## 冲突处理

如果出现冲突或无法推送：

1. 停止写入和提交。
2. 说明冲突文件。
3. 简述可能原因。
4. 等用户确认后再处理。

不要自动执行：

```bash
git push --force
git reset --hard
git checkout -- .
```

## 最小留痕规则

每次智能体完成一次任务，至少留下：

1. 阅读系统中的实际成果。
2. `10_智能体协作记录` 中的平台操作记录。
3. Git commit。
4. GitHub push。

一句话原则：

```text
阅读内容统一沉淀，平台操作单独留痕。
```
