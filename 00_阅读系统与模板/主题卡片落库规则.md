# 主题卡片落库规则

用途：确保每日阅读复盘中的主题归类，真正写入主题卡片库，而不是只停留在对话或每日回收里。

## 为什么需要这一步

之前的流程已经会在讨论中判断“这条划线属于哪个主题”，但实际记录主要写入：

- 每日阅读回收
- 书籍实践记录
- 方法迭代记录

主题卡片库没有同步更新，导致后续按主题检索时找不到这些沉淀。

所以从现在开始，每日复盘结束后增加一个固定步骤：主题落库。

## 每日主题落库流程

每天复盘结束后，Codex 必须执行：

1. 从当天讨论中选出 1-3 个最重要主题。
2. 判断对应主题文件是否已经存在。
3. 如果存在，就追加“来自《书名》的新增理解”。
4. 如果不存在，就新建主题卡片。
5. 每条内容要写清楚：
   - 日期
   - 来源书籍
   - 触发划线或观点
   - 我的理解
   - 可用原则
   - 现实案例或待观察问题

## 不要过度落库

不是每天所有划线都要进主题卡片。

优先进入主题卡片的内容：

1. 反复出现的主题。
2. 能改变判断的观点。
3. 能转化为行动原则的内容。
4. 和现实经历强相关的内容。
5. 以后很可能被调用的问题。

每天最多更新 1-3 个主题，避免主题卡片变成流水账。

## 主题卡片追加格式

```text
## 新增记录：YYYY-MM-DD《书名》

触发内容：

我的理解：

可用原则：

现实连接：

仍需观察：
```

## 每日复盘结束后的检查

每天复盘结束后，Codex 要确认：

```text
今日主题落库：
- 主题 1：已更新 / 未更新，原因
- 主题 2：已更新 / 未更新，原因
- 主题 3：已更新 / 未更新，原因
```

如果当天内容只是轻量阅读，没有产生值得沉淀的主题，也要写明：

```text
今日无主题落库：原因是……
```
