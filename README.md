# 阅读知识库

这是一个个人阅读知识库项目，用来记录读前目标、每日阅读回收、主题卡片、行动原则、书籍复盘和阅读方法迭代。

它的目标不是追求读书数量，而是让阅读真正转化成理解力、判断力、表达力和行动能力。

## 当前定位

这个知识库同时承担两个角色：

1. **阅读记录系统**：记录每本书从读前目标到读后复盘的完整过程。
2. **阅读方法实验场**：用连续 5 本书测试并优化一套适合自己的阅读方法，成熟后再考虑封装成 skill。

当前第一本实践书籍是《道商范蠡》。

## 核心原则

1. **你先思考，AI 后整理**  
   Codex 不直接替我总结，而是在我表达理解后，帮助我归纳、追问、落库。

2. **按问题读书，而不是按书读书**  
   每本书开始前先记录为什么读、希望回答什么问题、读完希望发生什么变化。

3. **按主题沉淀，而不是只按日期保存**  
   每日复盘只是入口，真正长期有价值的是主题卡片和行动原则。

4. **把阅读转化为行动**  
   好的划线最终要尽量变成现实场景中的判断、提醒或行动原则。

5. **及时同步到 GitHub**  
   每次完成回顾、总结或方法调整后，都要提交并推送，避免换电脑或本地异常导致资料丢失。

6. **支持多智能体协作**  
   Codex、WorkBuddy 或其他平台都可以维护本仓库，但必须遵守 [[AGENTS]] 和 [[多智能体协作规范]]。

## 日常阅读流程

1. 阅读 20 分钟。
2. 从当天划线或阅读感受中选 1-3 条“思考种子”。
3. 我先说自己的理解、现实连接和可能行动。
4. Codex 只做轻量整理，必要时写入每日回收或 [[00_本周阅读工作台]]。
5. 当天不强制更新主题卡片、行动原则或书籍卡片。
6. 如果划线很多，先放入“本周待整理划线”，每周再集中处理。

## 每周集中整理流程

每周固定一次，把平时积累的思考种子集中整理：

1. 回看 [[00_本周阅读工作台]] 和本周每日记录。
2. 选择本周最重要的 3 条洞见。
3. 更新 1-3 张真正有增量的主题卡片。
4. 选择 1 条可以实践的行动原则，写入 [[行动实践看板]]。
5. 生成一篇周复盘，写入 `02_每周阅读复盘/`。
6. 检查是否需要更新书籍卡片或方法迭代记录。
7. 按 [[GitHub同步流程]] 提交并推送。

## 每本书闭环

每本书至少留下：

1. 读前目标
2. 初始读法判断与 30% 复判
3. 每日思考种子或每日阅读回收
4. 书籍卡片
5. 主题卡片更新
6. 1-3 条行动原则
7. 至少 1 条行动实践记录
8. 读后目标回顾与最终档位确认
9. 方法迭代记录

## Obsidian 使用

这个目录可以直接作为 Obsidian vault 打开。

第一次打开时：

1. 打开 Obsidian。
2. 选择“打开本地文件夹作为库”。
3. 选择本目录。
4. 打开 [[00_知识库入口]]。

## GitHub 同步

当前目标是将整个阅读知识库迁移到 GitHub，作为长期备份和版本记录。

当前目录已经绑定 GitHub 仓库。每次完成阅读回顾、周复盘、书籍结项或方法调整后执行：

```bash
git status
git diff --stat
git add README.md AGENTS.md 00_知识库入口.md 00_本周阅读工作台.md 00_阅读系统与模板 01_每日阅读回收 02_每周阅读复盘 03_书籍卡片 04_主题卡片库 05_行动原则库 07_Obsidian视图 08_模板 09_索引 10_智能体协作记录
git commit -m "阅读复盘：YYYY-MM-DD 主题"
git push
```

更详细的流程见 [[GitHub同步流程]]。

## 多智能体协作

本仓库支持 Codex、WorkBuddy 和其他智能体平台共同维护。

所有平台必须遵守：

1. [[AGENTS]]
2. [[多智能体协作规范]]
3. [[GitHub同步流程]]

协作原则：

- GitHub 仓库是唯一主库。
- 阅读内容统一进入原有阅读系统目录。
- 平台操作记录单独进入 `10_智能体协作记录`。
- 每个平台开始前先拉取最新仓库，结束后写入协作记录并推送。
- 提交信息建议带平台名，例如 `[Codex] 方法调整：2026-06-03 增加多智能体协作规范`。

## 当前方法状态

- 奖励机制和积分功能已停用。
- 当前核心机制是：读前目标、读法判断、每日思考种子、每周集中整理、行动实践看板、读后复盘、GitHub 同步、多智能体协作留痕。
- 当前优化方向是：日常要轻，结项要完整，主题要复用，行动要回看。
